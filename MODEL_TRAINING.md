# Model training

> 🧪 **Experimental**: fine-tuning is not part of MiPizarra's current flow. The scripts live in
> [`experimental/`](experimental/README.md) and are not maintained at the pace of the rest of the project.

Fine-tuning is **optional**: MiPizarra works with the base model + RAG.
Train only if the evaluation shows that the base model is not enough.

> ⚠️ **Shared GPU**: if you train on the same machine that serves Ollama and the GPU does not have
> memory for both, stop Ollama during training. The `./experimental/finetune.sh` wrapper does this
> automatically.

## Folder layout

```
data/pdfs/                  ← Local material (not included in the repo)
data/dataset/
  train.jsonl               ← Final dataset (generated by generar_dataset.py)
  para_revisar.jsonl        ← Human-readable copy for manual review
outputs/<version>/
  lora_adapters/            ← LoRA weights after fine-tuning
experimental/docker/finetune/Dockerfile  ← Fine-tuning image
cache/                      ← HuggingFace cache
```

## Flow

### 1. Build the fine-tuning image (once)

```bash
docker compose build finetune
```

### 2. Generate the dataset

The dataset is generated from `data/exercises.json` and the `.md` files in `data/teoria/`. It can be
merged with additional local datasets (`data/dataset/extra_*.jsonl`) with `--incluir-entrenamientos`,
`--incluir-conocimiento` or `--incluir-externo`:

```bash
docker exec -it mipizarra-api python /app/experimental/generar_dataset.py --todo
```

⚠️ Review `para_revisar.jsonl` and remove bad examples from `train.jsonl` before training. A small,
clean dataset beats a large noisy one.

### 3. Fine-tuning

```bash
./experimental/finetune.sh               # 100 steps by default
./experimental/finetune.sh --steps 150
```

- QLoRA 4-bit by default; `--no-quantize` for bf16 LoRA if the GPU has enough memory.
- Uses Unsloth if installed; otherwise standard TRL.
- LoRA rank 8, alpha 16, dropout 0.05; examples longer than `--seq-len` are dropped instead of truncated.

Approximate steps by dataset size (≈5-8 epochs):

| Examples in train.jsonl | --steps |
|---|---|
| < 60 | 50 |
| 60-150 | 100 |
| 150-300 | 150 |
| 300-500 | 200 |
| > 500 | 250-300 |

If the loss drops below 0.5 before finishing → overfitting, lower `--steps`.
If it stays above 1.5 → the dataset is noisy or too heterogeneous.

Options: `--rank 16` (only with >500 examples), `--solo-atencion` (less VRAM), `--seq-len 2048`,
`--output outputs/<version>`.

### 4. Export to Ollama

```bash
docker compose run --rm finetune python experimental/exportar_a_ollama.py \
  --lora outputs/mipizarra-v1/lora_adapters --nombre mipizarra
```

Merges the adapters with the base model, produces a Q4_K_M GGUF and registers the model in Ollama.
If the automatic registration fails, the script prints the equivalent `ollama create` command.

### 5. Evaluate against the base model

```bash
docker exec -it mipizarra-api python /app/experimental/evaluar_modelo.py \
  --base qwen3:4b-instruct --finetuned mipizarra --n 20
```

It measures session structure, number of exercises, duplicates, exercise names that exist in the
library, valid diagram JSON, length and time. If the trained model does not clearly improve, do not
enable it: iterate on the dataset, not on `--steps`.

### 6. Enable the model

In `.env`: `OLLAMA_MODEL=mipizarra` and `docker compose up -d api`.

## Tips

- Version the outputs (`mipizarra-v2`, `v3`...) so you do not overwrite earlier models.
- Always keep the `lora_adapters/`: they are the trained model.
- The first training run downloads the base model into `./cache`.
